# A Tools Directory for Knowledge That Outlives Turnover

An opinionated, named-tool guide for building a team knowledge commons that survives contributor turnover. Organized around one governing principle ("infrastructure should follow function") and one portability test ("would your knowledge survive the tool dying?"), it maps tool choices to jobs (team knowledge base, individual notes, public site) and names a public/internal/private visibility-tier substrate mapping.
