# Metadata That Matters

How to design a small, durable set of metadata fields (title, type, status, owner, source, updated, tags) so a knowledge commons stays findable and trustworthy after the people who built it move on. Draws the type-vs-tag distinction (one type per document, many tags, a controlled vocabulary to prevent sprawl), recommends borrowing established field names (Dublin Core, Murmurations) rather than inventing new ones, and shows how to make the schema machine-enforced (Astro/Zod content collections, remark-lint-frontmatter-schema) so consistency does not depend on memory. Names status, owner, and source as the three non-negotiable "trust fields."
