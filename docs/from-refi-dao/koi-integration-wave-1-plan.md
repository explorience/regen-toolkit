```markdown
# KOI — One-Pager

**KOI** (Knowledge Organization Infrastructure) is a federated knowledge-graph protocol originated at BlockScience and adopted by the Regen Network ecosystem. ReFi DAO is an early adopter — we contribute work-in-kind in exchange for infrastructure support.

## What it solves

ReFi DAO produces knowledge across many surfaces (this repo, blog, podcast, member contributions, Notion). Each surface has its own format and its own access pattern. KOI gives us:

1. **A single addressing scheme** — every knowledge item has a stable RID like `orn:refidao.meeting:260424/refi-koi-discovery`.
2. **A federated graph** — peers (Regen, future ReFi BCN, etc.) can subscribe to public RIDs without copying our data.
3. **MCP access** — Claude Code can query the graph as if it were a database, with permissions and consent layers.

KOI does *not* generate knowledge. It connects it.

## How ReFi DAO uses it

Three integration modes (use any or all):

- **Consumer** — install `regen-koi-mcp` to query the public Regen federation from Claude Code. Zero setup. *Live as of 2026-04-25.*
- **Personal node** — run `personal-koi-mcp` locally against your vault. Lets you query your own knowledge through MCP. *Live as of 2026-04-25.*
- **Sovereign org node** — refi-dao-os runs its own KOI node, ingesting `packages/operations/`, `knowledge/`, `data/` and federating with peers. *Planned (Wave 2).*

## How to start

For installation: see [`docs/koi-personal-setup.md`](./koi-personal-setup.md).

For a deeper map of the protocol, the federation, the upstream repos, and the Regen ecosystem context: see the [research index](./research/koi-integration-overview.md).

For the strategic 7-phase plan and full architecture spec: see [`docs/agent-plans/koi-integration.md`](./agent-plans/koi-integration.md) and [`docs/superpowers/specs/2026-04-25-koi-integration-design.md`](./superpowers/specs/2026-04-25-koi-integration-design.md).

## Status (2026-04-25)

- ✅ Wave 1: Consumer + personal node working (this is what `koi-personal-setup.md` covers)
- ⏳ Wave 2: Sovereign node — gated on Sean meta-prompt + `legion-koi` license
- ⏳ Wave 3: Extract to `org-os/packages/koi/` — gated on Wave 2 + a 2nd instance ready to adopt

## Why this matters strategically

KOI integration is being designed from day one to become a **package of org-os** — every instance (refi-bcn-os, regen-coordination-os, future forks) inherits KOI capability when it adopts the package. ReFi DAO is the reference implementation.
```
