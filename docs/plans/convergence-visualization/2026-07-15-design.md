## Constraints (non-negotiable)

- **Never break the site build** (`npm run dev` / `build` / `preview`). New page is plain Astro (non-Starlight), like `knowledge-commons.astro`.
- **No new dependencies.** Schema map renders as inline SVG with a precomputed layout; no client-side graph library.
- **Public-safety by construction:** all surfaces derive from the working tree at build time. `kb-handoff/` (raw, unreviewed) exists only on the `regen-toolkit-os` dev branch → on `main` every surface auto-excludes it with zero conditional logic. Handoff-derived companion stubs likewise stay dev-only (same rule as `kb-handoff/` itself, decided 2026-07-15).
- **Aggregates only on public surfaces for raw content:** the schema map shows counts, never raw-object content.
- Derived outputs are **idempotent**: same inputs → byte-identical outputs (framework DoD discipline).

## Components

### 1 · `scripts/generate-kb-viz.mjs` (one derivation script feeds everything)

Reads `data/kb/*.yaml` + `kb-handoff/objects/**/*.yaml` (tolerate absence). Emits:

**a) `src/data/kb-schema-graph.json`**
```json
{
  "generated_from": "derived — rebuildable via npm run generate:kb-viz",
  "corpora": { "articles": 722, "handoff": 146 },
  "nodes": [ { "type": "resource", "total": 226, "raw": 210, "reviewed": 16, "byCorpus": {"articles": 226, "handoff": 0} } ],
  "edges": [ { "from": "resource", "to": "source-system", "label": "sourced_from", "count": 41 } ]
}
```
Edge derivation: scan object fields whose values resolve to known object IDs (relationship ID arrays, `sourced_from`-style fields); aggregate to type→type with the field name as label and an occurrence count. Sparse is acceptable and honest.

**b) Obsidian companion notes** (also emitted by this script — see §3).

Wiring: `"generate:kb-viz"` npm script; appended to the existing `knowledge` chain.

### 2 · `src/pages/convergence.astro`

Plain page (no Starlight involvement), the web rendering of `docs/CONVERGENCE.md`:

1. One-sentence story + three-builds panel (Matty's spec · the machine · Heenal's site)
2. Pipeline visual — inline SVG/CSS of the loop (ingest → accept gate → raw → human gate → commons → site render), live counts injected at build from the JSON
3. Schema map — inline SVG, precomputed circular layout (~12 type nodes, colored by type, total/raw/reviewed per node, labeled edges)
4. Evidence links (crosswalk, DoD conformance, `/handoff`, `/self-ingestion`) + who-holds-what table

Add one link from `/framework` → `/convergence`. Do not touch the homepage.

### 3 · `kb-graph/` Obsidian companion notes

```
kb-graph/
  README.md                  # what this is + how to regenerate
  Knowledge Commons.md       # master hub → all type hubs
  hubs/<type>.md             # ~12 hubs: counts + links to member stubs
  <type>/<object-id>.md      # ~868 stubs
```

Stub format: frontmatter `type`, `maturity`, `corpus`, `ai_assisted`; body = title, short description, `[[hub]]` wikilink, wikilinks to referenced objects (same ID resolution as edge derivation), pointer to the source YAML path. Hubs link every member so graph view clusters by type. Committed (derived-and-rebuildable convention, like `index.json`).

### 4 · `docs/canvases/the-machine.canvas`

Hand-authored, following the 16 existing canvases: pipeline stages as groups; corpora flowing in; the two gates (accept, review-promote) visually distinct; people lanes (Matty editorial · Heenal Layers 2+7 · Luiz technical · Durgadas CSIS lens) attached where they plug in; file nodes linking to `docs/CONVERGENCE.md`, the crosswalk, and the skills. Master canvas gains a link node.
