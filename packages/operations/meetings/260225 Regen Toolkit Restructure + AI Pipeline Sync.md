# Regen Toolkit — Restructure + AI Writing Pipeline Sync

**Date:** 2026-02-25
**Type:** Planning
**Source:** Curated by the team in the repo (`docs/meeting-notes/2026-02-25.md`); migrated to canonical org-os layout 2026-04-26.

## Key Decisions

- Move from track-based structure to **tag-based**: each article has one canonical location; tracks become **filter views**, not folders.
- Add tagging schema: `primary category`, `function`, `persona`, `maturity stage`.
- Restructure into **10 modules** (not tracks): Orientation, Web3 Literacy, Local Node Lifecycle, Governance & Treasury, Capital & Funding, Economic & Token Design, Impact Architecture, Community & Culture, Risk & Resilience, Operational.
- Adopt **"ship V1 with whatever we have"** stance — 50–150 articles however imperfect, rather than waiting for perfection.
- Reach out to other knowledge-gardening groups (Ethereum Localism, ReFi Commons, Superbenefit) — **don't recreate what already exists.**
- AI writing pipeline (Heenal): 5-stage — Research → Write → Verify → Review → Critique → Publish — using cheap models (~$0).
- Working docs (research / factcheck / critique) stored in repo alongside articles.

## Discussion Summary

### Restructuring (Matt)
The current track-based structure was creating duplication — tracks were doing double duty as both content structure AND user pathways, which confused contributors. Matt proposed a tag-based architecture: every article gets one canonical home plus tags that drive filter views (which become the user-facing "tracks"). The 10 proposed modules cover web3 literacy + local-node lifecycle + governance/treasury/funding + impact + community + risk + operational dimensions.

### AI Writing Pipeline (Heenal)
5-stage pipeline ran 5 pilot articles end-to-end; ready for human review. Cheap-model strategy keeps cost ~$0 per article. All intermediate working docs (research notes, fact-checks, critique outputs) live in the repo so the pipeline is auditable. Goal: ship V1 with 50–150 articles, accept imperfection over delay.

### Knowledge Commons Collaboration
Multiple groups are doing similar knowledge-gardening work — risk of recreating what exists. Rather shared ReFi Commons ontology links:
- knowledge-server.superbenefit.dev (Rather's working ontology)
- growingcommons.substack.com/p/types-of-knowledge-commons-wiki-pages (Simon Grant)

The team agreed reach-out is needed before more structural decisions get baked in.
